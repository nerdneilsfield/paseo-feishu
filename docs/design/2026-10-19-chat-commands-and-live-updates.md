# 插件内命令、历史消息与动态回复

状态：待用户审阅，尚未实现。本文扩展 [SPEC.md](./SPEC.md) 中只支持两个文本命令、只在任务结束后通知的 v0.1 范围。

## 目标与验收结果

用户在飞书内发送 `/help` 或 `/history` 时，由插件直接处理，不创建 Agent turn，也不调用 Agent 的发送接口。普通对话执行期间，同一张飞书卡片持续显示助手已经公开输出的进展，用户无需等到整轮结束。

继续使用现有的单用户白名单、私聊、已有 Agent 绑定和消息去重。权限审批仍使用独立审批卡片。新增功能不保存对话正文到插件状态文件或日志。

## 插件内命令

| 输入 | 插件行为 |
| --- | --- |
| `/help` | 返回 `/help`、`/sessions`、`/status`、`/history`、`/history more` 的用途，以及绑定后普通文字会发给 Agent 的说明；未绑定和 Paseo 离线时也可使用 |
| `/sessions` | 保持现有会话选择行为 |
| `/status` | 保持现有绑定状态行为 |
| `/history` | 从当前绑定会话的最新记录开始，显示最近一页用户和助手消息，并重置历史翻页位置 |
| `/history more` | 显示当前历史位置之前的一页；尚未执行 `/history` 时提示先执行它 |

内置命令在普通提示词转发和未绑定分支之前识别。`/help`、`/history` 的非法参数在插件内返回用法，不转发给 Agent。其他 provider 命令仍沿用普通提示词转发路径，例如 `/compact`；本次不增加未知命令拦截。

未授权用户、非私聊和重复消息沿用现有拒绝规则。`/history` 在未绑定、切换中、Paseo 离线、目标会话不存在或已归档时返回明确提示，不调用 Agent 发送接口。

## 历史消息

历史来自 Paseo `agent.timeline.refetch()`，使用 `tail` / `before`、SDK 的 `{ epoch, seq }` 游标和 `projected` 视图。只展示 `user_message` 与 `assistant_message`，标明角色和 SDK 提供的时间；不展示 reasoning、工具输入输出或审批命令全文。

每页最多 10 条可见消息，按本页从旧到新的顺序展示。每条消息最多显示 1200 字符，整页最多 12000 字符；截断处明确标记。单条命令最多请求 5 个 SDK 页面，每页最多 50 条 timeline 记录，避免工具事件很多时无限扫描。扫描上限内没有可见消息时，说明本次扫描范围没有用户或助手消息；如果还有更早记录，允许继续 `/history more`。

使用 SDK 返回的 `startCursor` 读取更早页面，不自行构造游标。一个 SDK 页面中已经读取、尚未展示的用户和助手消息保存在内存缓冲区，先展示完缓冲区，再沿游标请求更早页面，不能因一次只显示 10 条而跳过其余记录。缓冲区只保留可展示的文本摘录和排序标识，不保留原始工具记录。按序列位置确定先后顺序；SDK 边界是否包含游标由协议验证用例确认，重复边界记录只展示一次。

历史命令串行执行，翻页位置在飞书发送成功后才推进；读取或发送失败保留先前位置。游标与缓冲区只保存在内存，并关联当前绑定版本；切换会话、插件重载或 timeline epoch 失效后重置，旧位置不会用于另一个会话。历史请求过程中绑定发生变化时，丢弃旧请求结果并提示重新查询。

历史读取错误与历史为空分开处理。游标过期、历史缺口或 SDK 报错时如实说明，不把错误当成“没有历史”。

## 动态回复

采用现有 `sendCard()` 与 `updateCard()`，每轮一张回复卡片。卡片起始状态为“处理中”，正文随公开助手消息更新；结束状态为“已完成”“失败”或“已取消”。最终卡片保留本轮可见回复，超出 12000 字符时标记截断，并提示通过历史查看。

选择这种方式是因为仓库已有卡片发送与更新能力，可以沿用当前权限。逐条发送进展会刷屏；SDK 的专用流式接口涉及另一套消息生命周期，本次不引入。

更新由真实的 timeline 事件触发，不按计时器重复发送“仍在处理”。有新内容时每秒最多提交一次卡片更新；期间发生的变化合并为最新快照。每张卡的更新串行执行，结束更新排在先前的更新之后，避免旧进展覆盖最终结果。无正文时仍可显示处理中或等待审批等真实状态，不镜像 reasoning 或原始工具输出。

完成状态以 `agent.turn_ended` 及其 `outcome` 为权威，不根据空闲状态猜测结束。收到结束事件时，先同步封存该轮、停止进展定时器，再等待既有的通知去重持久化；迟到的 timeline 事件不能重新开启该轮。若建卡尚未结束，在后台等待建卡及在途更新完成，再进行最终更新，不能提前额外发送一份结束消息。hook 内不等待飞书网络。

成功定格动态卡片后不再重复发送一份完成文字；建卡或最终更新失败时，保留现有最终文字通知路径。最终通知仍遵守既有幂等规则，不重试 Agent 提示词。

## 订阅、切换与断线

只订阅当前绑定 Agent 的 timeline。插件恢复绑定或用户切换成功后建立订阅；向 Agent 转发普通提示词前，等待订阅的 `ready`，避免提示词已经执行却尚未开始观察。观察失败时，回复发送失败原因，不悄悄退化成缺少进展的执行。

订阅就绪后读取当前 timeline，以便绑定时正在运行的任务也能显示进展。订阅是 live-only，初始快照读取期间先缓存 live 事件，再按 epoch、序列位置和当前 turn 合并。快照替换已协调的本地视图，不能把快照文本再次追加到已拼接文本之后。正常 live 助手片段按协议逐段追加，不使用 messageId 替换或文本前缀猜测。

`subscription_restored` 后补查当前轮缺失内容，在协调结束前不转发新的提示词；首次订阅已完成的 `ready` 不能代替重连后的协调。`replacement` 使旧 epoch 和历史位置失效。缺口不可恢复时标明进展不完整。缺少可用序列元数据时，由事件触发合并后的快照补查，不虚构去重标识或盲目追加；此补查同样节流，不增加后台轮询。

每次绑定生成新的观察代次。异步历史结果、订阅回调和排队的卡片更新都校验代次、Agent 和 chat；切换或关闭后不再安排旧绑定的新发送与更新。已经发到飞书接口的请求可能完成，插件无法撤回在途请求。停止插件时释放订阅和更新定时器，不停止 Agent。

## 实现职责

- `server/session.ts`：内置命令路由、绑定版本、历史请求和翻页位置；内置命令从转发路径提前返回。
- `server/paseo.ts`：SDK 历史页和实时订阅的窄接口，保留游标、epoch、序列及 SDK 错误语义。
- `server/notifications.ts` 和一个专用进展模块：当前绑定的观察生命周期、快照合并、节流、最终状态与既有结束通知的协调。
- `server/channel.ts`、`server/cards.ts`：沿用卡片发送更新和现有日志，增加回复卡片的展示。
- `index.server.ts`、`server/contracts.ts`：装配及内部契约，明确订阅和定时器的释放责任。

不增加依赖、环境变量开关、后台轮询或新的持久化格式。按先命令与历史、再动态回复的顺序实现，各自使用新的 implementation agent，顺序验证并提交。

## 验证

| ID | 必须观察到的结果 |
| --- | --- |
| C1 | 未绑定或已绑定时 `/help` 都由插件回复，Agent 发送调用为零；非法参数同样不转发 |
| C2 | `/history` 与 `/history more` 只读取当前绑定历史，正确过滤和翻页；工具事件密集时请求次数有上限，未展示消息不会被跳过 |
| C3 | 历史为空、离线、归档、读取失败、过期游标和查询期间切换都有明确结果，不泄露旧绑定内容 |
| C4 | 发出普通提示词之前订阅已就绪；助手第一段进展在 turn 结束前可见，后续更新同一张卡片 |
| C5 | 高频片段合并更新；最终状态不会被迟到的进展覆盖；成功完成的动态卡片不再重复发送结束文字 |
| C6 | 取消、失败、审批、订阅恢复和 epoch 替换不会伪造完成或重复拼接正文 |
| C7 | 切换和关闭释放旧订阅、定时器并丢弃旧异步结果；日志不包含历史和回复正文 |

使用现有 Vitest 测试和类型检查验证上述行为；真实飞书验收包括 `/help`、两页 `/history`、一个含两段间隔进展的任务、最终卡片和切换会话。只重载插件，不重启 daemon。自动化通过与真实平台已验证的范围分别记录。
