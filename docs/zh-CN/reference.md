# 参考

飞书（Feishu）和 Lark 是同一个产品的两个名字，本文统称“飞书”；环境变量等代码里出现的名字沿用 `feishu`。

本文列出 paseo-feishu 的配置、聊天命令、通知规则、状态文件和已知限制。安装与首次使用见 [setup.md](./setup.md)。

## 配置

插件只从环境变量读取配置，没有配置文件或插件设置项。daemon 在启动时继承启动环境；插件启动时从 daemon 继承环境，并读取一次配置。之后在终端 `export` 或修改 shell 配置文件，都不会更新已运行 daemon 的环境。`paseo plugin reload paseo-feishu` 和 `paseo reload` 不会导入终端的新环境变量。修改变量后，需要让 daemon 从更新后的启动环境重新启动；重启会中断运行中的任务，请在任务结束后操作。

修改 `FEISHU_OWNER_OPEN_ID` 后，用新启动日志 `startup.config.loaded` 的 `ownerId` 末 6 位核对实际生效值。`sender_not_allowed` 表示消息已经到达 SDK，但发送者与插件实际读取的授权用户不一致；即使终端里变量正确，daemon 仍可能持有旧值。

| 变量 | 必需 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `FEISHU_APP_ID` | 是 | 无 | 飞书应用的 App ID，以 `cli_` 开头 |
| `FEISHU_APP_SECRET` | 是 | 无 | 飞书应用的 App Secret |
| `FEISHU_OWNER_OPEN_ID` | 是 | 无 | 唯一被授权的飞书用户的 open_id，以 `ou_` 开头 |
| `FEISHU_DOMAIN` | 否 | `feishu` | `feishu` 或留空：国内飞书（`https://open.feishu.cn`）；`lark`：国际版 Lark（`https://open.larksuite.com`）；其他值按完整 URL 使用（私有部署）。`feishu`、`lark` 不区分大小写 |
| `PASEO_URL` | 否 | `ws://127.0.0.1:6767/ws` | daemon 的 WebSocket 地址 |
| `PASEO_PASSWORD` | 否 | 无 | daemon 的明文密码。daemon 未设置密码时不需要 |
| `STATE_FILE` | 否 | `$PASEO_HOME/plugins-data/paseo-feishu/state.json` | 状态文件路径 |
| `PASEO_HOME` | 否 | `~/.paseo` | 仅用于推导 `STATE_FILE` 的默认路径 |

必需变量缺失任何一个时，插件向日志写出缺失的变量名，然后保持空载：不连接 Paseo，不连接飞书，`paseo plugin ls` 仍显示 `running`。变量值为空字符串同样视为缺失。

`PASEO_URL` 只支持 TCP 的 WebSocket 地址。unix socket 不受支持。

## 聊天命令

下表以外的文本都不是命令。已绑定会话时，它们作为提示词发给该 agent。

| 输入 | 作用 |
| --- | --- |
| `/sessions` | 发送会话选择卡 |
| `/status` | 显示当前绑定会话的标题、短目录和真实状态 |
| `/help` | 打开本地导航，未绑定或 Paseo 离线时也可用 |
| `/history` | 显示最近十条用户/助手摘录，重置翻页位置 |
| `/history more` | 显示更早摘录；须先执行 `/history` |

命令大小写敏感，前后空白会被忽略。`/sessions`、`/status` 须是整条消息；首词精确为 `/help` 或 `/history` 时始终在本地处理，非法参数返回用法。`/helpful`、其他 provider 命令（如 `/compact`）及普通中文消息沿用原转发规则。

历史读取 SDK projected 页，过滤 reasoning 和工具记录。单次最多扫描五页、每页五十条，按序列展示最多十条消息；未展示摘录暂存在内存。每条摘录最多 1000 字符、卡片文字最多 12000 字符，截断会明确提示回 Paseo 查看全文。发卡成功后才推进位置，读取或发送失败保留位置；切换、重载或游标失效会重置。读取错误、缺口和空历史分别说明。原生菜单配置见 [设置指南](./setup.md#可选配置机器人菜单)。

## 消息处理规则

插件对每条收到的消息按下列顺序判断，命中第一条即停止。

| 条件 | 行为 |
| --- | --- |
| 发送者不是 `FEISHU_OWNER_OPEN_ID`，或不是私聊，或发送者是机器人 | 丢弃，不回复 |
| 不是文本消息 | 丢弃，不回复 |
| 消息是上表本地命令（含 `/help`、`/history` 非法参数） | 本地导航或返回用法，不产生 Agent turn |
| 正在切换会话 | 回复“切换中：此消息未发送，请切换后重发。” |
| 尚未绑定会话 | 发送会话选择卡，原消息不转发 |
| Paseo 未连接 | 回复“Paseo 未连接，消息未发送”，不排队 |
| 已绑定且已连接 | 发给绑定的 agent |

消息按飞书的 `message_id` 去重。通过通道检查的消息在执行本地命令或转发前记录 ID，重投不会再次触发 agent。

发给 agent 后的回复有四种：

| 回复 | 含义 |
| --- | --- |
| Paseo 已受理（非任务完成），进展将在回复卡显示。 | Paseo 已接受这条消息。agent 的回复不在这里，完成时另有通知 |
| 发送结果不确定，请到 Paseo 核对，未自动重发 | 请求已发出但没拿到确认。插件不会重发，避免重复执行 |
| 当前会话不可用（不存在或已归档），消息未发送，请重新选择会话。 | 绑定的 agent 已不存在或已归档 |
| Paseo 拒绝了这条消息，消息未发送。 | Paseo 返回了拒绝 |

## 卡片

| 卡片 | 标题 | 按钮 |
| --- | --- | --- |
| 会话选择 | Paseo · 选择会话 | 每个未绑定的 agent 一个**切换**（当前绑定的位置显示**当前**）；**上一页**、**下一页**；**刷新** |
| 当前会话 | Paseo · 当前会话 | **选择会话**、**历史**、**命令说明** |
| 帮助 | Paseo · 帮助 | 四个本地导航按钮 |
| 命令说明 | Paseo · 命令说明 | 命令列表，以及**帮助**和其余本地导航 |
| 历史 | Paseo · 会话历史（摘录） | 有更早记录时显示**更早**；**回到最新**及本地导航 |
| 审批请求 | Paseo · 审批请求 | **允许本次**、**拒绝** |
| 审批已处理 | Paseo · 审批已处理 | 无 |

按钮每行最多两个、等宽；单按钮铺满一行，文字使用按钮默认居中布局。**拒绝**是普通按钮，不用红色：拒绝是安全退出，强调色留给真正会执行动作的那一边。本地导航不重复指向当前卡片自身：在“当前会话”卡上看不到**状态**，在“命令说明”卡上以**帮助**回到帮助卡。

会话选择卡每页 5 个 agent。当前绑定的 agent 排在最前，其余按最近活动时间从新到旧排列。agent 状态显示为：运行中、空闲、异常、已关闭（对应 `closed`）、启动中、未知。

每个 agent 占一块：加粗标题一行，下一行是 provider、状态、目录和相对活动时间，**切换**按钮和这一块在同一行。那个位置对当前绑定显示“当前”而不是按钮——点了只会再发一张同样的卡；保留占位是为了让所有标题左边缘对齐。活动时间用相对值（“2 分钟前”）而不是钟点，因为选择卡要回答的是会话有多新，不是几点几分；历史卡里每条消息仍用绝对时间。

回复卡先给会话标题和助手正文，最后一行放最近事件时间。标题配色只标记需要你动手的状态：处理中、正在使用工具为蓝色，等待授权、等待回答为橙色，已完成为绿色，失败为红色，已取消为灰色。运行中但还没有公开正文时，正文显示“等待公开进展…”；已结束但没有正文时显示“暂无公开助手内容”。

通道集中校验回调结构和身份；会话操作检查当前卡片与绑定关系，历史翻页只认最新历史卡片的消息 ID。

**旧卡片会失效。** 每次发出新的会话选择卡，版本号加一，并记下这张卡的消息 ID。点击的卡片消息 ID 或版本号与记录不一致时，提示“卡片已过期，请重新打开”。发送 `/sessions` 获取新卡片。

**不会无限等待。** 每一处等待网络调用都有上限，因为一次卡住就会让私聊永久沉默：

| 等待 | 上限 | 恢复方式 |
| --- | --- | --- |
| 观测就绪 | 10 秒 | 拒绝本次提交并告知未发送 |
| 单次写卡（进展、选择、最终） | 10–15 秒 | 下一帧继续写；建卡超时会重试而不是放弃；迟到的旧进展不能重绘已封口的卡 |
| `/history` 的单页读取 | 10 秒 | 下一次 `/history` 能执行，而不是永远排队 |
| 发往飞书的 REST 请求 | 20 秒 | SDK 层；不设上限时卡住的 API 会挂住整个机器人 |
| 动态回复卡的单次读取 | 20 秒 | 释放读取槽并把卡片标为状态待核对；下一拍重新读取 |

最终答复的回读同样是 15 秒上限。超时、报错，或只翻到长轮次尾部时，卡片会说明结果不完整，而不是把读取失败显示成“暂无公开助手内容”。

文本消息在处理中抛错时仍会回一条“未发送”。历史和写卡两处之所以必须有上限，是因为它们跑在同一条串行链上：没有上限时，一次挂起就把之后每个请求排在后面，机器人什么也不回。

卡片点击使用独立队列，不与消息排队。因此一个仍在等待的消息处理不会挡住审批或选择卡点击。

**卡片格式。** 卡片使用 JSON 2.0 结构，需要飞书客户端 7.20 或更高版本；更低版本只显示标题和升级提示。

**更新限制。** 飞书只允许在消息发出后 14 天内更新卡片，同一条消息每秒最多更新 5 次。

**飞书对卡片回调的限制。** 飞书要求在 3 秒内响应卡片点击。处理超过 2.5 秒仍没有结果时，插件返回 loading 提示，保证响应落在限制之内；其他提示类型有 info、warning、error。切换、刷新和审批的实际工作在后台继续，完成后更新卡片或发送文字回复。

## 通知

通知只发给当前绑定的 agent。没有绑定会话时不发送任何通知。

| 事件 | 条件 | 飞书收到的内容 |
| --- | --- | --- |
| agent 一轮对话结束 | 该 agent 当前仍绑定，且事件带轮次 ID | 当前轮更新回复卡并发简短通知；迟到的旧轮另发文字结果 |
| agent 请求权限 | 该 agent 是当前绑定的 agent | 审批卡，或“请回 Paseo 处理”的提示卡 |
| 权限请求在别处被处理 | 飞书里有对应的审批卡 | 审批卡更新为“已在 Paseo 处理” |
| agent 被归档 | 该 agent 是当前绑定的 agent | 文字提示当前绑定不可用，需重新选择 |

`<标题>` 取 agent 的标题；没有标题时取 agent ID 的前 8 位。

**动态回复。** 公开助手消息更新在同一张卡上，每秒最多更新一次；最终正文最多 12000 字符。卡片操作失败时用文字通知交付结果。当前绑定 agent 的旧轮结束事件迟到时，另发一条带轮次号的文字结果并去重，不改当前回复卡片。不缓存旧卡片；没有轮次 ID 的结束事件直接忽略。

结束事件不再携带对话内容（Paseo 0.13 起 `timeline` 恒为空）。最终答复按 `turnId` 通过 `context.paseo.agents.ref(...).timeline.refetch` 向前翻页回读，最多 10 页、每页 100 条；更长的轮次只取到答复的尾部。回读失败时通知照发，只是没有正文。

**审批卡与提示卡。** 只有权限类型为工具调用，且可选动作恰好是一个允许和一个拒绝时，才生成带按钮的审批卡。其他请求（自由文本问题、计划审阅、模式切换、多选项等）只发提示卡，要求回 Paseo 处理，飞书里不提供按钮。

**不重试。** 通知发送失败时只记录日志，不重试。每条通知在发送前先记录幂等键，所以同一 agent 的同一轮对话、同一权限请求不会重复通知，代价是发送失败的通知也不会补发。

**审批卡的更新范围。** “在别处被处理”时能更新的审批卡，只限本次插件运行期间发出的最近 500 张。插件重启后，重启前发出的审批卡不会再被更新。点击这类卡片上的按钮时，插件会先向 Paseo 查询该请求是否仍待处理，已处理的会提示“该请求已处理”，不会重复提交。

## 审批

点击**允许本次**或**拒绝**后：

1. 插件检查当前 agent 与聊天，提交接口读取一次待办并校验允许/拒绝动作。
2. 向 Paseo 提交决定。
3. 提交后再查询一次，确认该请求已不在待处理列表里。
4. 把卡片更新为“已允许”或“已拒绝”。

同一请求的重复点击只提交一次。第 3 步发现请求仍待处理时，回复“审批未成功（failed）…”，并且不会重复提交；确认失败不会标记为已处理；请先到 Paseo 核对，再决定是否重试。

## 状态文件

默认路径为 `~/.paseo/plugins-data/paseo-feishu/state.json`，权限 `0600`。写入时先写临时文件，再 `fsync`，最后原子替换。

| 字段 | 内容 | 上限 |
| --- | --- | --- |
| `binding` | 当前绑定的 agent ID、飞书会话 ID、用户 open_id、版本号、会话选择卡的消息 ID | 1 条 |
| `deliveries` | 已处理的消息 ID 及状态（`claimed`、`accepted`、`rejected`、`unknown`） | 最近插入的 500 条 |
| `notified` | 已发送通知的幂等键 | 最近插入的 500 条 |
| `decidedPermissions` | 已处理的权限请求 ID 及结果（`allow`、`deny`、`resolved_elsewhere`） | 最近插入的 500 条 |

状态文件不保存对话内容、密码或 App Secret。

超出上限的旧记录被丢弃。因此插件重启后，若飞书重投一条已落出这 500 条窗口的旧消息，它可能再次被转发。

**状态文件损坏。** 文件不是合法 JSON，或结构不符合预期时，飞书长连接不会启动，日志里报告文件路径，插件不会覆盖原文件。修复或删除该文件后，重新加载插件（`paseo plugin reload paseo-feishu`）。删除后绑定会丢失，需要重新选择会话。

## 日志

用 `paseo plugin logs paseo-feishu` 查看。常见条目：

| 日志 | 含义 |
| --- | --- |
| `Plugin ready` | 插件已加载。不代表飞书或 Paseo 已连接 |
| `missing required env: …` | 列出的必需变量缺失，插件空载 |
| `could not resolve bot identity …` | 飞书拒绝了 App ID 或 App Secret，机器人能力未启用，或域名与账号不符 |
| `startup.session.loading` / `startup.session.ready` | 开始读取状态文件 / 会话已就绪 |
| `feishu.connected` / `paseo.connected` | 对应连接已建立；`startup.ready` 包含当时的 `paseoConnected` 状态 |
| `feishu.event.observed` | SDK 已观察到消息事件，包含消息 ID 和类型；此观察点在 SDK 内建处理之后执行 |
| `feishu.policy.rejected` / `feishu.message.rejected` | SDK 策略 / 插件过滤了消息，`reason` 说明原因，用户 ID 只显示末 6 位 |
| `session.routed` | 消息进入命令或转发分支，例如 `/status` 对应 `action=status` |
| `session.consume.started` / `session.consume.succeeded` | 开始 / 完成保存消息去重状态；只有 started 时可能卡在状态保存 |
| `feishu.send.started` / `feishu.send.succeeded` / `feishu.send.failed` | 回复发送开始 / 成功 / 失败，包含耗时和 SDK 提供的错误信息 |
| `feishu.channel.error` / `session.failed` / `startup.failed` | SDK 内部、会话处理或异步启动失败 |
| `feishu.reconnecting` / `feishu.reconnected` | 飞书长连接正在重连 / 已恢复 |

新增日志以 `[paseo-feishu]` 加单行 JSON 输出。处理消息时，`sourceMessageId` 将命令路由和回复发送关联到同一条输入消息。错误日志提取错误类型、错误码、原因、HTTP 状态、飞书 API 错误码和请求 ID（底层 SDK 提供时），不序列化完整请求、响应或原始事件。已知 App Secret、Paseo 密码、Bearer token 和 URL 查询参数会被脱敏。

复现无反馈问题时，私聊发送 `/status`，然后重新运行 `paseo plugin logs paseo-feishu`；此命令返回日志快照，不持续跟随。若有拒绝日志，查看 `reason`；若有 `session.routed`，沿相同 `sourceMessageId` 查看保存状态和发送结果。错误信息来自底层库，分享日志前仍需检查是否含敏感内容。

## 生命周期

- 插件启动时先发起 Paseo 连接（不等待结果），读取状态文件，然后启动飞书长连接。Paseo 连接失败只写日志，飞书照常启动；连接由 SDK 自动重连，连上之前消息会收到“Paseo 未连接，消息未发送”。
- 状态文件读取失败（含文件损坏）时，飞书长连接不会启动，插件保持空载。
- 插件停止时，同时关闭飞书连接、会话处理和 Paseo 连接。停止预算约 4 秒，超时则被宿主强制结束。
- 插件不会创建、归档、分离或停止任何 agent，停止插件也不影响正在运行的 agent。

## 已知限制

- 仅支持一个 daemon、一个飞书机器人、一个授权用户，仅私聊。
- 仅支持文字消息输入。
- Paseo 断开期间的消息不排队、不补发。
- 通知发送失败不重试。
- 去重与幂等记录各保留最近插入的 500 条。
- 依赖版本不锁定。上游的破坏性更新会让插件在加载或运行时失败，此时需要更新插件。
- 以下环节尚未用真实飞书应用验证：长连接、卡片渲染与按钮回传、3 秒回调时限、真实消息收发。以下环节尚未在真实 daemon 上验证：`turn_ended` 与权限相关 hook 的触发、向 agent 发送消息、提交审批、带密码的连接。
